## Why

Today the MicroIDE editor has solid plumbing — multi-caret, soft wrap, syntax highlighting, undo/redo, LSP-driven completion/hover/diagnostics/formatting, and project search — but it stops short of the day-to-day editing affordances that VSCode and Zed users treat as table stakes. There is no code folding, no matching-bracket highlight or jump, no auto-close pairs, no surround, no language-aware indent on `{` / `(`, no toggle-comment, no move/duplicate/delete-line, no add-cursor-at-next-match, no occurrences highlight, no indent guides, no save-time normalization (trim trailing whitespace, ensure final newline, auto-detect indent), no symbol outline, and no snippet expansion. As a result the editor still feels like a syntax-highlighted text box rather than a code editor, and every plugin/LSP integration we ship lands on top of an underpowered host surface.

The shipped foundations (TextViewport, RuntimeSyntaxRegistry, PluginHost contribution registries, LSP client, view-model render path) are now mature enough that these capabilities can land as host-owned, deterministic features that compose with — rather than replace — the existing primitives.

## What Changes

- Add **code folding** to the editor: indent-based folding everywhere, plus bracket-pair folding when a language declares its bracket set; folding controls in the gutter, fold-aware caret motion, fold-aware soft-wrap, and a "Fold All / Unfold All" command. Sticky scroll keeps the enclosing parent line(s) pinned at the top of the viewport.
- Add **bracket and pair handling**: highlight the bracket matching the bracket adjacent to the caret, jump to matching bracket (`Ctrl+Shift+\`), auto-close pairs as the user types (`(`, `[`, `{`, quotes), surround a non-empty selection with a typed pair (`(`, `[`, `{`, quotes), and skip-over-close-character behavior. **Smart indent** triggers on language pairs: pressing Enter after an open pair indents one extra step; typing a close pair on an indent-only line dedents that line one step.
- Add **code shaping actions** to the action registry: toggle line comment (`Ctrl+/`), toggle block comment (`Shift+Alt+A`), move line up/down (`Alt+Up/Down`), duplicate selection or line (`Shift+Alt+Up/Down`), delete line (`Ctrl+Shift+K`), indent/outdent selection (multi-line `Tab` / `Shift+Tab`), sort selected lines, add cursor at next match of selection / word under caret (`Ctrl+D`), add cursor at all matches in selection (`Ctrl+Shift+L`), and highlight occurrences of the word under the caret in the visible viewport.
- Add **presentation affordances**: indent guides at every indent step (with active-indent emphasis when the caret is inside a block), optional render-whitespace mode that draws tab/space markers, and host-owned "scroll past end of file" toggle.
- Add **save-time normalization**: trim trailing whitespace, ensure exactly one trailing newline, and auto-detect the file's indent style (tabs vs N spaces) on first open from existing content. All three are user/project settings that plug into the existing `WorkspaceSettingsRegistry`.
- Add **symbol outline**: a built-in sidebar view backed by LSP `textDocument/documentSymbol` (with a deterministic regex-based fallback for languages without an LSP), wired through the existing `WorkspaceSidebarRegistry` so it reuses sidebar policy/persistence.
- Add **snippet expansion**: tab-triggered expansion of plugin-contributed snippets with placeholder navigation (`Tab` / `Shift+Tab`) and final-tab-stop exit, surfaced through completion entries and a dedicated `Insert Snippet…` overlay.
- Extend the **plugin language contract** so syntax plugins can additionally declare bracket pairs, auto-close pairs, surround pairs, line comment marker, block comment markers, indent/outdent regex hints, fold markers, and snippets — consumed by the host, not by plugin rendering.
- Every new capability above SHALL be individually enable/disable-able by the user through (a) a `WorkspaceSettingsRegistry` entry that round-trips through user and project config, (b) a stable `ActionId` toggle command that is keyboard-bindable, and (c) a checkable menu entry under `View` (presentation toggles), `Selection` (multi-cursor toggles), or `Preferences → Editor` (input/save toggles). The Settings overlay SHALL list every toggle in a single "Editor → Essentials" group so users can audit and flip them in one place. Disabling a capability SHALL revert the editor to the prior built-in behavior with no residual UI.

All UI is host-owned: plugins contribute data (pairs, comment markers, snippets, fold hints) and providers (LSP `documentSymbol`); rendering, redraw, and policy stay on the host.

## Capabilities

### New Capabilities
- `editor-block-structure-affordances`: code folding (indent + bracket), fold gutter, fold-aware navigation, sticky scroll, indent guides, render whitespace, symbol outline sidebar view.
- `editor-language-pair-and-indent`: matching-bracket highlight, jump-to-matching-bracket, auto-close pairs, surround-selection-with-pair, language-aware smart indent on Enter / close-bracket dedent, plugin-declared bracket and pair contracts.
- `editor-code-shaping-actions`: toggle line/block comment, move/duplicate/delete line, indent/outdent selection, sort lines, add-cursor-at-next-match, add-cursor-at-all-matches-in-selection, highlight occurrences, snippet expansion with placeholder navigation, and save-time normalization (trim trailing whitespace, ensure final newline, auto-detect indent on open).

### Modified Capabilities
- `editor-multicursor-and-wrap`: extend with the "add caret at next match" / "add caret at all matches in selection" semantics so the multi-caret model stays the single source of truth for these new commands; clarify how fold ranges interact with multi-caret motion.

## Impact

- Affected source: `src/editor/TextViewport.{h,cpp}` (fold ranges, smart indent, auto-pair, surround, occurrences scan), new `src/editor/FoldingModel.{h,cpp}`, new `src/editor/IndentGuides.{h,cpp}`, new `src/editor/SnippetEngine.{h,cpp}`, `src/editor/EditorViewRenderer.{h,cpp}` (fold gutter, indent guides, occurrence highlights, sticky scroll, whitespace glyphs), `src/editor/SyntaxHighlighter.h` / `RuntimeSyntaxRegistry.{h,cpp}` (plugin-declared bracket / comment / pair / fold contract), `src/plugin/PluginHost*` (Lua surface for the new contract + snippets), new `src/workspace/WorkspaceLanguageContract.{h,cpp}` host service, new outline sidebar view in `src/workspace/WorkspaceSidebar*`, new actions in `WorkspaceActionTypes*`, and corresponding `WorkspaceSettingsRegistry` entries.
- Affected protocols: LSP client gains `textDocument/documentSymbol` and (optionally) `textDocument/foldingRange`, both routed through the existing async wake-event path.
- Affected persistence: per-user and per-project settings files gain `editor.fold.*`, `editor.brackets.*`, `editor.indent.*`, `editor.view.*`, `editor.save.*`, `editor.outline.*`, `editor.occurrences.*`, `editor.shaping.*`, and `editor.snippets.*` keys (each with a `.enabled` boolean plus tuning knobs), all flowing through the existing `PersistedRecordReader` / `PersistedRecordWriter`. New `ActionId` toggle entries register through `WorkspaceCommandRegistry`, `WorkspaceMenuRegistry`, and `WorkspaceKeybindingRegistry` so every capability is reachable from command, menu, and keybinding alike.
- Affected docs: `docs/active-work.md`, `guidelines/plugins.md`, `guidelines/ui-shell.md`, and a new `docs/editor-essentials.md` covering folding, snippets, and the language contract.
- Affected tests: new fixtures under `tests/EditorFoldingTests.cpp`, `tests/EditorPairHandlingTests.cpp`, `tests/EditorShapingActionsTests.cpp`, `tests/EditorSnippetTests.cpp`, `tests/EditorRenderViewModelAllocationTests.cpp`, plus extensions in existing `tests/WorkspaceShellPluginTests.cpp` and `tests/PluginHostTests.cpp`.
- Affected performance harness: every new per-frame and per-keystroke hot path gets an isolated harness scenario alongside the aggregate `typing_large_file` / `scroll_large_file` baselines. New scenarios committed under `tests/perf/baselines/`: `editor_fold_recompute`, `editor_fold_viewport_refresh`, `editor_sticky_scroll_scroll`, `editor_indent_guides_paint`, `editor_render_whitespace_paint`, `editor_outline_lsp_refresh`, `editor_outline_regex_fallback`, `editor_bracket_match_caret_motion`, `editor_auto_close_typing`, `editor_smart_indent_typing`, `editor_surround_multi_caret`, `editor_occurrences_scan`, `editor_add_cursor_next_match`, `editor_shaping_multi_caret`, `editor_toggle_comment_large_selection`, `editor_sort_lines_large`, `editor_snippet_expand`, `editor_snippet_placeholder_edit`, `editor_save_normalization`, `editor_indent_detect_open`. New 50 000-line fixtures under `tests/perf/fixtures/editor_essentials_50k_cpp/` and `editor_essentials_50k_py/`, plus a 1 MB fixture under `editor_essentials_1mb/`. Existing aggregate scenarios remain the merge gate; isolated scenarios provide diagnostic resolution and per-capability ownership tracking. Architectural-lint gains a `CheckEditorViewModelVectorsAreReused` rule asserting per-frame view-model vectors preserve capacity across frames.
- Out of scope: minimap, command palette redesign, semantic-tokens-driven indent, snippet marketplace, AI-driven inline completion (still excluded by `non-ai-product-scope`).
