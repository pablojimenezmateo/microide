## Why

The 2026-04-29 `comprehensive-tech-debt-cleanup` change locked workspace ownership and persistence shape, but it left two structural gaps that are now load-bearing for everything that follows. First, performance evidence is still human-driven: every change record has to attach a hand-captured `MICROIDE_STARTUP_TRACE` or `MICROIDE_PERF_TRACE` log on a developer machine, and our automated tests run under `SDL_VIDEODRIVER=dummy` which never exercises the real paint path — so we cannot detect render-side regressions, idle-CPU regressions, multi-project memory regressions, or scenario-level slowdowns (project switch, tab thrash, linter-on-save, scroll-through-large-file) without a human looking at numbers. Second, the architectural-lint test, the workspace coordinator TUs, and several legacy/dual-representation files (`WorkspaceShellTestAccess.h` ~1500 lines, `WorkspaceTabCoordinator.cpp` ~1364 lines, `util/SingleLineText.*` coexisting with `editor/SingleLineEditor.*`, the legacy persistence importer) are exactly the kind of debt the prior change said to track and finish. Now is the moment to do both, because the perf harness is the foundation on which every subsequent service extraction, render-path edit, and feature merge will rely.

## What Changes

- **NEW** Add an automated performance harness (`microide_perf`) that drives a real SDL window through scripted scenarios on a software renderer (not the dummy video driver), captures structured metrics (per-frame percentiles, CPU samples, RSS, allocations, redraw counts, wake-up counts), compares against committed baselines, and fails CI on regression beyond a documented tolerance. Initial scenarios cover: cold startup with no project, cold startup with a small project, cold startup with a large project, opening five projects and switching among them, opening twenty file tabs and cycling through them, typing a paragraph in a small file, typing a paragraph in a large file, scrolling a large file end-to-end, project search (literal + regex), linter-on-save (plugin diagnostics provider triggered by save), opening a compare tab plus a merge tab, opening the chat pane and pasting a long transcript, and a 30-second idle soak.
- **NEW** Add `tests/perf/` baselines (committed JSON, one file per scenario) plus a `--update-baseline` CLI flag with a documented review process for intentional baseline changes.
- **NEW** Wire the harness into `ctest` as a separate, longer-running suite (`microide_perf_tests`) and into a CI matrix entry that gates merges on the same machine class used for baselining.
- **NEW** Add bug-detection tooling: ASAN, UBSAN, and TSAN CI variants for `microide_tests`; a fuzzing harness for `PersistedRecordReader` (truncated, swapped tags, corrupt CRC, nested vec/optional edge cases) and the legacy importer; a fuzzing harness for the search regex compiler and the git-blame parser; an allocation-counter fixture so render-path tests can assert "zero allocations during draw"; a long-soak (8h) headless run that asserts zero idle wake-ups and bounded RSS growth.
- Tighten the architectural-lint test: cover every `src/workspace/WorkspaceShellRender*.cpp` file (not just seven), flip `src/plugin/*.cpp` ≤ 800 lines from soft to hard-fail, add a hard-fail rule that `Workspace*Coordinator*.cpp` ≤ 800 lines, add a hard-fail rule that view-model structs (any type whose name ends in `ViewModel`) contain no `WorkspaceShell`/`Coordinator`/`Service` fields, add a check that no file outside `src/workspace/PersistenceService.{h,cpp}`, the legacy importer, and the persistence layer opens project-state, user-config, session, or conversation files, and replace the regex-based `try`/`std::sto*` check with a tokenizing scan that catches `try`-block bodies the current heuristic misses.
- **BREAKING** Collapse `src/util/SingleLineText.{h,cpp}` into the canonical `editor/SingleLineEditor.{h,cpp}` model. Every workspace state model that currently stores `util::SingleLineTextState` is migrated to the shared model; the older type and its free helpers are deleted.
- Decompose oversized coordinator TUs into focused services or coordinator-shards, each at or below 800 lines: `WorkspaceTabCoordinator.cpp` (1364), `WorkspaceActionServices.cpp` (1086), `WorkspaceChatTranscript.cpp` (1170), `WorkspaceKeyInputCoordinatorSurfaces.cpp` (735, soft-cap), `WorkspaceLspClient.cpp` (1126), `WorkspacePersistenceBinaryFormat.cpp` (1119), `WorkspaceLayout.cpp` (995). Each split lands with its own architectural-lint scope and a perf-harness scenario covering the affected hot path.
- Trim `WorkspaceShellTestAccess.h` (~1500 lines) by replacing test-access methods that duplicate service-public APIs with direct service calls in the affected fixtures; cap the remaining file at ≤ 600 lines.
- Migrate the chat composer to the shared single-line edit primitives where its multiline behavior is not in play (selection-range invariants, copy/cut/paste/select-all on the single visible line) so the documented "multiline exception" shrinks to actual multiline operations.
- Investigate and fix the `WorkspaceLspClient` race noted in the chat-phase-2 memory record; gate the fix behind the new TSAN CI variant.
- Replace per-change "include trace output" expectations in `performance-budgets` with "harness baseline updated and CI passes". Keep human-readable traces (`MICROIDE_STARTUP_TRACE`, `MICROIDE_PERF_TRACE`) as the debugging fallback when the harness reports a regression.
- Schedule the `legacy-persistence-cleanup` follow-up (release +2) so the one-shot importer and `.legacy` file handling are removed once the harness has a clean release of green baselines without legacy files.
- **BREAKING** All harness scenarios become a merge gate. Changes that move a baseline must update the corresponding baseline JSON in the same commit and explain the move in the change record.

## Capabilities

### New Capabilities

- `performance-harness`: durable contract for the automated, headless-but-real performance harness — scenario format, metric set, baseline storage, regression-gate semantics, and the SDL software-renderer-based driver.
- `bug-detection-tooling`: durable contract for sanitizer CI variants, fuzzing harnesses for the typed persistence and external parsers, allocation-counter test support, and the long-soak idle run.

### Modified Capabilities

- `performance-budgets`: replace the human-in-the-loop "attach trace output" requirement with "harness baseline updated and CI passes"; keep the existing budget thresholds and add scenario-level budgets for project switch, tab cycling, linter-on-save, and idle wake-ups.
- `workspace-architecture`: add the additional lint invariants (full render-surface coverage, view-model back-reference forbidden, coordinator TU size cap, plugin TU size hard-fail, single-line-text canonicalization, persistence-file-I/O boundary check).
- `persisted-state-format`: add a fuzz-resilience requirement (the reader and importer SHALL survive truncated, swapped, and CRC-corrupt inputs without aborting) and an end-of-life clause for the one-shot legacy importer.
- `shared-edit-primitives`: require a single source-of-truth representation for single-line edit state (`editor::SingleLineEditor`); forbid the parallel `util::SingleLineTextState`.

## Impact

- Affected code: new `tests/perf/` tree (driver, scenarios, baselines), new `src/perf/` module (harness instrumentation surfaces), `tests/ArchitectureInvariantsTests.cpp`, `src/util/SingleLineText.*` (deleted), every workspace state model that stores `util::SingleLineTextState`, the seven oversized coordinator TUs listed above, `src/workspace/WorkspaceShellTestAccess.h` (trimmed), `src/workspace/WorkspaceLspClient.cpp` (race fix), and the workspace and provider files that currently consume the legacy single-line type.
- Affected APIs: internal-only. No public C ABI exists; plugin-facing Lua APIs are unchanged. Test-fixture APIs change because shell test-access shrinks; affected fixtures move to direct service calls.
- Affected CI: a new `microide_perf_tests` CTest entry, three new sanitizer CI matrix entries (ASAN, UBSAN, TSAN), one new fuzzing CI entry, one new long-soak CI entry. The perf gate runs on a documented reference machine class so baselines stay comparable.
- Affected on-disk artifacts: none new in the user data directory. New repo artifacts under `tests/perf/baselines/*.json` (committed) and `tests/perf/scenarios/*.{lua,cpp}` (committed). The `legacy-persistence-cleanup` follow-up is scheduled (not landed) here.
- Affected docs: `AGENTS.md`, `CLAUDE.md`, `dev-docs/project/active-work.md`, `dev-docs/project/known-tech-debt.md`, `dev-docs/performance/runtime-profiling.md` (replace human-driven flow with the harness as primary, traces as fallback), `dev-docs/performance/startup-tracing.md` (same), `guidelines/performance.md`, `guidelines/architecture.md`, `guidelines/testing.md`. New `dev-docs/performance/perf-harness.md` describes the scenario DSL, baseline workflow, and how to add a scenario.
- Affected tests: every workspace fixture that currently calls `WorkspaceShellTestAccess` methods removed by the trim. Coordinator decomposition steps add fixtures around the new seam.
- Risk: the perf gate can produce false positives on a noisy CI runner. Mitigation: scenarios run with N≥10 iterations, percentile-based comparison rather than mean, documented tolerance per scenario, and a one-line `// allow-baseline-move: <reason>` mechanism for intentional baseline changes that the change record must justify.
- Risk: software-renderer numbers do not match GPU-renderer numbers on user machines. Mitigation: the harness measures relative regression, not absolute target performance; the budget thresholds in `performance-budgets` continue to apply as separate, manually validated checks for absolute-target work.
